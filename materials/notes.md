# Конспект лекций (СРВ)

## Лекция 2. Основные объекты и механизмы работы ОС
- Поток — наименьшая единица выполнения, которую ядро ОС назначает на процессор; потоки одного процесса делят общую память.
- Контекст процесса — состояние регистров, программного счётчика и режима работы; при переключении сохраняется и восстанавливается.
- Состояния: готов, выполняется, ожидает.
- Невытесняющее планирование: поток работает, пока сам не отдаст управление. Вытесняющее (квантование): поток снимают, когда кончился квант или он ушёл в ожидание.
- Приоритетное планирование: выбирается готовый поток с наивысшим приоритетом; с одними приоритетами низкоприоритетный поток может вообще не получить процессор.
- Прерывание — остановка текущих команд для обработки события (аппаратные от устройств, внутренние — исключения процессора).

## Лекция 3. Синхронизация потоков
- Разделяемый ресурс используют несколько потоков; критический — тот, который одновременно может использовать только один поток.
- Критическая секция — участок кода, работающий с критическим ресурсом. Взаимное исключение — в критической секции в каждый момент только один поток.
- Гонка (race condition) — результат зависит от порядка или скорости потоков. Data race — два потока обращаются к одной памяти, хотя бы один пишет, синхронизации нет.
- Deadlock — потоки ждут ресурсы друг друга. Четыре условия: взаимное исключение, удержание и ожидание, нет принудительного отбора, циклическое ожидание.
- Starvation (голодание) — поток долго не может захватить ресурс, потому что другой быстро отпускает и снова захватывает его.
- Блокировка: захватить перед работой с ресурсом, остальные ждут, после работы освободить. Нельзя прерывать поток между «проверить» и «установить» блокирующую переменную, поэтому нужна неделимая команда (CMPXCHG на x86).
- Недостаток блокирующей переменной: ждущий поток постоянно её опрашивает и впустую тратит процессорное время.
- Семафор — счётчик с атомарными P (захват, ждёт пока 0) и V (освобождение). Мьютекс — двоичный семафор, освободить его может только владелец.
- Атомарная операция выполняется «в один шаг», другой поток не увидит её наполовину сделанной. В C/C++ любая операция неатомарна, пока явно не сказано иное. В лабах использовать только std::atomic.
- Основные атомарные операции: load, store, exchange, compare_exchange (CAS), fetch_add.

## Лекция 4. С++ и многопоточное программирование
- std::mutex: lock() блокирует (ждёт, если занят), try_lock() пробует без ожидания, unlock() освобождает.
- Обёртки над мьютексом: lock_guard (захват в конструкторе, освобождение в деструкторе — RAII, для одного мьютекса), unique_lock (гибкий, нужен для condition_variable), scoped_lock (C++17, сразу несколько мьютексов).
- RAII — ресурс берётся в конструкторе и освобождается в деструкторе, поэтому не забудешь unlock.
- lock_guard работает с любым типом, у которого есть lock() и unlock() (BasicLockable), то есть и с самодельным мьютексом.
- compare_exchange(expected, desired): если значение == expected — записать desired и вернуть true, иначе записать текущее значение в expected и вернуть false.
- strong — без ложных отказов; weak — может вернуть false даже при равенстве (spurious failure), но дешевле, поэтому используется в цикле.
- memory_order: relaxed — только атомарность; acquire/release — для захвата и освобождения блокировки; seq_cst — по умолчанию, самый строгий.
- Самодельный мьютекс можно построить из atomic_bool + compare_exchange или exchange, либо на семафоре (C++20).
- Многопоточные ошибки трудно воспроизвести: удачный запуск не доказывает, что ошибки нет.

## Лекция 5. Сопрограмма
- Корутина (сопрограмма) — функция, которая может приостановиться и потом продолжиться с того же места; многозадачность кооперативная: задача сама отдаёт управление.
- В отличие от потоков, переключение между корутинами задаёт программа, а не планировщик ОС.
- Если корутины работают в одном потоке и других потоков нет, каждый отрезок между приостановками — фактически критическая секция, мьютексы не нужны.
- Корутины хороши для лёгких задач без долгих вычислений, например отрисовка прогресс-бара. Блокирующая операция внутри корутины опасна: она блокирует весь поток.
- Стековые корутины (волокна) имеют свой стек; бесстековые (C++20) хранят состояние в объекте корутины и тесно связаны с вызывающим кодом.
